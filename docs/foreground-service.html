Foreground service declaration

H4b1ts · de.h4b1ts.app · demonstration of FOREGROUND_SERVICE_SPECIAL_USE

Recorded on a Samsung Galaxy S25, Android 16, from the signed release build.

What the recording shows

  1. The Shield screen, where the user has granted the permissions and can test that blocking works.
  2. The user leaves the app and opens an app they had previously chosen to block.
  3. The lock screen appears immediately, naming the blocked app and offering a countdown and a one-minute exception.

Why the special use type

The app blocks apps the user has chosen to block. To do that it must know which app is in the foreground while the screen is on. When a blocked app is opened, H4b1ts shows a lock screen immediately, so the result is directly visible to the user.

The service starts only once the user has enabled blocking and picked at least one app. It pauses when the screen turns off and shows an ongoing notification the whole time it runs.

None of the predefined foreground service types describes this: no data is synced — the app has no INTERNET permission at all — no media is played, no location requested, no camera or microphone used. shortService does not apply either, because blocking has to keep working rather than end after a few minutes.

Only the package name of the currently visible app is read, and only in memory. No usage history and no usage duration is stored, and nothing leaves the device.
